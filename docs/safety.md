# Safety model and limits

The example uses fictional member data only. Do not point this first pass at a real banking system. It has no production identity provider, credential vault, legal approval workflow, or complete data loss prevention. See [tenant security](tenant-security.md).

## Enforced boundaries

The server checks a target's origin and exact path before opening it, before each automation step, and after actions. A link or form action destination is checked before clicking. Action types are allowlisted. Automated clicks with risky words such as transfer, delete, pay, submit, or confirm are blocked and routed to a human. A capability's own allowed origin cannot expand the server allowlist. The browser adapter requires a unique visible locator and does not execute arbitrary model-supplied JavaScript. Signed bearer tokens identify fixture users. SQLite tenant roles govern caller and operator access; a separate signed browser cookie binds each run to an actor and tenant.

The SQLite fixture stores salted `scrypt` password hashes, three tenants, 25 fictional customers, and their accounts. All account reads pass through the tenant gateway. A shared base artifact holds parameter references and output names, never example input values or extracted data. Tenant bindings hold routes and locators; replay requires an approved binding and a short-lived scoped grant in addition to identity. Structured events store action names, selected locators, and condition codes; known input values, long numbers, and currency amounts are scrubbed from observations. The demo form sends the member ID in a POST body so it does not appear in access-log URLs. The model receives parameter schemas and redacted observations, not invocation values. The caller receives raw outputs in the API response because those are the requested results and should handle them according to its own policy.

The ignored `.env` holds real LAN addresses. Published binding files and saved evidence replace them with `192.168.z.zz` for the API machine and `192.168.x.xx` for the browser machine. Binding loads resolve the API placeholder from the configured allowed origin before replay, which still passes the normal URL policy. The demonstration evidence index distinguishes historical schema 1.1 traces from current schema 2.0 results.

The authorized catalog lists only approved bindings for a tenant. Invocation uses a qualified `name@artifact-id` selected from that catalog, typed values, the identity bearer token, and a matching `secure_permissions` grant. FastMCP forwards these to the same gateway endpoints and does not access customer tables. Draft evaluation requires a separate `evaluate` grant and tenant operator role; approved replay cannot use it. Assisted fallback is opt-in for a tenant operator, permits one model proposal for a missing locator, and keeps the approved artifact unchanged. A proposal is accepted only after the normal policy and final checkpoint checks.

## Known limits

The allowlist checks top-level URLs, visible link/form destinations, and browser-context network requests before they leave the browser. Popups and non-HTTP browser behavior still need review for a production adapter. Text redaction is heuristic and does not recognize all PII; a production system needs field classification and output-specific controls. The operator UI records a fixture operator ID but does not prevent simultaneous operators across processes. The remote Playwright server is unauthenticated; protect the port with a LAN/VPN and firewall. The in-process run registry is not durable. Browser screenshots are deliberately not persisted because they may contain account data; failure evidence is a scrubbed control snapshot.

Risky controls may be operated by a human with an operator role in the run tenant, but the human still cannot navigate the browser outside the configured URL policy through this API. The current demo has no transaction control. Before adding one, define explicit action policy by capability and operator role, idempotency rules, transaction review checkpoints, and an audit record of the human identity and approval.
